Model Parallel.py代码实现的是 PyTorch 中的**模型并行（Model Parallelism）**。与常见的数据并行（Data Parallelism，每个 GPU 持有一份完整的模型，处理不同的数据批次）不同，模型并行是指**将同一个模型的不同层（Layers）分配到不同的 GPU 上**运行。

当模型由于参数量过大、单张 GPU 显存无法容纳时（例如超大语言模型或巨型视觉模型），通常会采用这种策略。

下面对这段代码进行逐模块的详细拆解和说明：

---

### 一、 数据预处理与加载

```python
transform = transforms.Compose(
    [transforms.Resize((224, 224)), transforms.ToTensor()]
)

train_dataset = datasets.CIFAR10(
    root="./data", train=True, download=True, transform=transform
)
train_loader = DataLoader(train_dataset, batch_size=64, shuffle=True)

```

* **图像尺寸调整**：ResNet-18 默认接受 $224 \times 224$ 分辨率的输入，而 CIFAR-10 的原生图片尺寸是 $32 \times 32$，这里通过 `transforms.Resize((224, 224))` 进行了上采样。
* **数据加载**：使用 `DataLoader` 组合成批次（Batch Size = 64），便于后续迭代训练。

---

### 二、 模型并行结构设计 (`ModelParallelResNet`)

这是代码的核心部分，展示了如何手动将一个标准的 ResNet-18 拆分到两张不同的显卡（`cuda:0` 和 `cuda:1`）上。

```python
class ModelParallelResNet(nn.Module):

  def __init__(self):
    super(ModelParallelResNet, self).__init__()
    resnet = models.resnet18(weights=ResNet18_Weights.DEFAULT)

    # 【前半部分】放在 cuda:0
    self.stage1 = nn.Sequential(
        resnet.conv1,
        resnet.bn1,
        resnet.relu,
        resnet.maxpool,
        resnet.layer1,
        resnet.layer2,
    ).to("cuda:0")

    # 【后半部分】放在 cuda:1
    self.stage2 = nn.Sequential(
        resnet.layer3,
        resnet.layer4,
        resnet.avgpool,
    ).to("cuda:1")

    # 全连接层放在 cuda:1
    self.fc = nn.Linear(resnet.fc.in_features, 10).to("cuda:1")

```

* **设备切分策略**：
* **`stage1`（前半部分）**：包含初始的卷积层、池化层以及前两个残差块（`layer1`, `layer2`），被明确指定通过 `.to("cuda:0")` 放入第一张显卡。
* **`stage2`（后半部分）**：包含后两个残差块（`layer3`, `layer4`）和平均池化层，通过 `.to("cuda:1")` 放入第二张显卡。
* **分类层 (`fc`)**：输出 10 分类（针对 CIFAR-10），同样放在 `cuda:1`。



---

### 三、 前向传播与跨设备数据流 (`forward`)

```python
  def forward(self, x):
    # 1. 输入送入 cuda:0 并运行前半部分
    x = x.to("cuda:0")
    x = self.stage1(x)

    # 2. 中间激活值传送到 cuda:1，运行后半部分
    x = x.to("cuda:1")
    x = self.stage2(x)

    # 3. 展平并通过全连接层
    x = torch.flatten(x, 1)
    x = self.fc(x)
    return x

```

* **数据流动过程**：
1. 输入数据从 CPU 读入后，首先被显式移动到 `cuda:0`，由 `stage1` 进行特征提取。
2. **关键步骤**：`stage1` 的输出（即中间激活值/Intermediate Activations）必须通过 `x = x.to("cuda:1")` **显式地从第一张显卡传输到第二张显卡**。
3. 在 `cuda:1` 上完成剩下的网络计算和全连接层映射，并返回最终输出。



---

### 四、 训练循环与反向传播

```python
num_epochs = 2
for epoch in range(num_epochs):
  running_loss = 0.0
  for i, (inputs, labels) in enumerate(train_loader):
    # 输入送到 cuda:0，标签送到模型最终所在的 cuda:1
    inputs, labels = inputs.to("cuda:0"), labels.to("cuda:1")

    optimizer.zero_grad()

    # 前向传播（输出在 cuda:1）
    outputs = model(inputs)
    loss = criterion(outputs, labels)

    # 反向传播与优化
    loss.backward()
    optimizer.step()

    running_loss += loss.item()

```

* **标签位置**：因为模型的最终输出（`outputs`）在 `cuda:1` 上，计算损失（Loss）时，真实标签（`labels`）也必须在 `cuda:1` 上（`labels.to("cuda:1")`），否则会报设备不匹配错误（Device Mismatch Error）。
* **自动求导（Autograd）**：虽然模型分布在不同的 GPU 上，但 PyTorch 的底层计算图会自动追踪跨设备的张量操作。当执行 `loss.backward()` 时，**梯度会自动沿着前向传播的反方向，从 `cuda:1` 跨设备回传到 `cuda:0**`，更新两张卡上的模型参数。

### 五、 这种原生模型并行的局限性（专家提示）

这段代码展示了模型并行的基本原理，但在实际大规模工程中，这种“朴素的模型并行（Naive Model Parallelism）”存在一个致命缺陷：**GPU 利用率极低（计算气泡 / Pipeline Bubble）**。

* **串行等待**：当 `cuda:0` 在计算 `stage1` 时，`cuda:1` 处于闲置状态等待输入；而当数据传到 `cuda:1` 计算 `stage2` 时，`cuda:0` 又闲置了。两张卡无法同时工作。
* **通信开销**：每一批次数据在两张卡之间传输中间特征（通过 PCIe 总线）会带来额外的通信延迟。

> **工业界替代方案**：
> 如果您拥有多张 GPU 且模型能够放入单卡，通常建议优先使用**数据并行（DDP, `torch.nn.parallel.DistributedDataParallel`）**。如果模型真的太大单卡放不下，现代深度学习通常会采用流水线并行（Pipeline Parallelism, 如 PyTorch PiPPy）**或**张量并行（Tensor Parallelism）来最大化多卡并发效率。
