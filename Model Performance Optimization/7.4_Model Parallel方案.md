在深度学习中，当模型参数量极其庞大（例如数十亿、数百亿甚至数万亿参数的大语言模型），以至于**单张 GPU 的显存完全无法容纳整个模型**时，单纯的“数据并行（Data Parallelism）”就会失效（直接报显存 OOM 错误）。

此时，必须采用**模型并行（Model Parallelism, MP）**。模型并行的核心思想是：**“数据不动，动模型”**——将模型的网络层、张量或参数切分到多张 GPU 上，由多张 GPU 协同完成前向和反向计算。

模型并行主要分为三大主流方案：**张量并行（Tensor Parallelism, TP）**、**流水线并行（Pipeline Parallelism, PP）**以及现代大模型标配的**零冗余优化器分片（ZeRO / FSDP）**。

---

## 一、 为什么需要模型并行？

* **传统数据并行（DDP）的局限**：每一张 GPU 上都必须完整复制一份模型参数、梯度和优化器状态。
* **模型并行的突破点**：通过空间维度上的切分，将庞大的模型“拆碎”分发到不同的 GPU 显存中，从而突破单卡显存的物理上限。

---

## 二、 三大主流模型并行方案详解

### 1. 张量并行（Tensor Parallelism, TP，如 Megatron-LM）

* **核心思想**：**层内并行（Intra-layer Parallelism）**。将神经网络**单个层内部**的矩阵乘法（例如 Transformer 中的 Attention 投影层 `Q/K/V`、MLP 全连接层）按行或按列切分到多张 GPU 上。
* **经典结构（以 Megatron-LM 的 MLP 为例）**：
* **第一层矩阵乘法（Column-parallel）**：将权重矩阵按列切分到两张卡上（GPU 0 存左半边，GPU 1 存右半边）。输入 $X$ 同时输入两张卡，各自独立计算，然后通过 **All-Gather** 或 **All-Reduce** 拼接结果。
* **第二层矩阵乘法（Row-parallel）**：将权重矩阵按行切分。


* **优缺点**：
* **优点**：能够极大地降低单张卡的显存压力，单层计算可以在多卡间紧密协同。
* **缺点**：由于单层计算频繁需要跨卡通信（All-Reduce / All-Gather），**对硬件互联带宽要求极高**。通常必须局限在同一台机器内部的高速互联（如 NVIDIA NVLink / NVSwitch）中，无法跨服务器长距离部署。



---

### 2. 流水线并行（Pipeline Parallelism, PP，如 PipeDream）

* **核心思想**：**层间并行（Inter-layer Parallelism）**。如果模型有几十层（例如 GPT 拥有 96 层），我们可以把前 32 层放在 GPU 0，中间 32 层放在 GPU 1，最后 32 层放在 GPU 2，像工厂的流水线一样串行执行。
* **核心挑战与优化（微批次调度）**：
* **气泡问题（Bubble）**：如果直接串行（GPU 0 算完传给 GPU 1，GPU 1 算完传给 GPU 2），在任一时刻总有卡在闲置等待，导致 GPU 利用率低下。
* **微批次调度（Micro-batching，如 1F1B 策略）**：将一个大的 Batch 切分成多个微批次（Micro-batches）。让不同的 GPU 交替执行前向（Forward）和反向（Backward）计算，最大程度填满流水线空隙，减少气泡。


* **优缺点**：
* **优点**：通信开销远低于张量并行，支持跨机器、跨节点部署。
* **缺点**：调度复杂，流水线“气泡”会带来一定的算力浪费。



---

### 3. 零冗余优化器分片（ZeRO / FSDP - Fully Sharded Data Parallel）

严格来说，ZeRO 是数据并行与模型并行的结合体（通常被称为**分片数据并行**），但在现代大模型训练中，它扮演着与模型并行完全一致的降显存角色。

在传统的 DDP 中，每张卡都完整复制一份**优化器状态（Optimizer States）**、**梯度（Gradients）**和**模型参数（Parameters）**。ZeRO 通过分片（Sharding）消除了这种冗余：

* **ZeRO-Stage 1**：分片**优化器状态**（显存直降 4 倍）。
* **ZeRO-Stage 2**：分片**优化器状态 + 梯度**（显存直降 8 倍）。
* **ZeRO-Stage 3**：分片**优化器状态 + 梯度 + 模型参数**（显存随 GPU 数量线性减少）。
* **工作机制（以 Stage 3 为例）**：在前向和反向传播时，当前卡需要计算哪一部分参数，就通过动态通信（All-Gather）临时把参数拉取过来，计算完立刻释放，从而让单卡能够训练远超自身显存极限的巨型模型。

---

## 三、 现代大模型的终极形态：3D 并行（3D Parallelism）

在训练如 LLaMA-70B、GPT-4 等超大规模模型时，单一种并行方案往往捉襟见肘。工程上通常会将上述方案组合使用，称为 **3D 并行**：

1. **张量并行（TP）**：局限在单机内部（利用 NVLink 超高速带宽），切分单层矩阵。
2. **流水线并行（PP）**：跨机器连接，将深层模型按层垂直切分。
3. **数据并行 / FSDP（DP）**：在上述两维切分的基础上，对整个集群剩余的算力进行大规模数据并行扩展。
---
## 四、 3D并行
在训练超大规模语言模型（如数百亿甚至数万亿参数的 LLM，例如 GPT-4、LLaMA-70B+）时，单一的并行策略（如单纯的数据并行或模型并行）已经无法满足显存和计算吞吐的需求。

因此，业界提出并广泛采用了**3D 并行（3D Parallelism）**。它将**张量并行（Tensor Parallelism, TP）**、流水线并行（Pipeline Parallelism, PP）**和**数据并行/FSDP（Data Parallelism, DP）三种策略有机结合，构成了现代超大规模集群训练的基石。

---

### （1） 什么是 3D 并行？

3D 并行本质上是一个**三维度的笛卡尔坐标系**。在一个拥有成百上千张 GPU 的集群中，每一张 GPU 在整个集群中都有一个特定的“坐标”，分别负责不同维度的计算与通信：

1. **第一维度：张量并行（TP）** —— 解决“单层网络太大、单卡放不下”的问题（层内切分）。
2. **第二维度：流水线并行（PP）** —— 解决“网络层数太多、单卡放不下”的问题（层间切分）。
3. **第三维度：数据并行 / FSDP（DP）** —— 解决“单批次计算太慢、需要横向扩展吞吐”的问题（数据分片）。

假设集群总共有 $N$ 张 GPU，通常满足以下数学关系：


$$\text{Total GPUs} = \text{TP} \times \text{PP} \times \text{DP}$$

---

### （2） 3D 并行的三个维度详解

#### 1. 张量并行（Tensor Parallelism, TP）

* **切分维度**：**层内切分（Intra-layer）**。
* **核心原理**：将 Transformer 内部的单个矩阵乘法运算（如 Attention 的 Q/K/V 投影、MLP 的全连接层）拆分到多张卡上。例如，把一个巨大的权重矩阵按列或按行切成两半，分别放在 GPU 0 和 GPU 1 上。
* **通信特征**：每一层的前向和反向传播都需要进行频繁的跨卡通信（如 `All-Reduce` 或 `All-Gather`）。
* **硬件限制**：由于通信频率极高且对延迟极其敏感，**张量并行必须局限在同一台机器内部**，依赖高速硬件互联（如 NVIDIA NVLink / NVSwitch）。

#### 2. 流水线并行（Pipeline Parallelism, PP）

* **切分维度**：**层间切分（Inter-layer）**。
* **核心原理**：如果模型有 96 层，可以将前 32 层放在节点 A，中间 32 层放在节点 B，最后 32 层放在节点 C，像工厂流水线一样串行执行。
* **通信特征**：相邻的流水线阶段之间传递激活值（Activation）和梯度，通信数据量相对较小。
* **优化策略**：为了解决“气泡（Bubble）”闲置问题，通常会引入 **Micro-batch（微批次）** 调度算法（如 1F1B 策略），让各张卡交替处理不同的微批次。

#### 3. 数据并行 / FSDP（Data Parallelism / ZeRO-DP）

* **切分维度**：**数据与显存分片（Data & State Sharding）**。
* **核心原理**：在完成了 TP 和 PP 的模型切分后，集群中剩下的算力和 GPU 组，可以用来做大规模的数据并行（或现代的 FSDP 零冗余优化器分片）。每个数据并行组持有一份模型切片的副本，各自处理不同的数据 Batch，并在最后通过 `All-Reduce` 同步梯度。
* **通信特征**：主要在梯度回传时进行全局或组内同步。

---

### （3） 3D 并行的协同工作流程

在一个典型的 3D 并行集群中，数据流动和计算的协作关系如下：

1. **Micro-batch 输入**：一个大的 Global Batch 被切分成多个 Micro-batch。
2. **Pipeline 传递**：Micro-batch 依次送入流水线的第一个阶段（PP Stage 0）。
3. **Tensor 并行计算**：在流水线的每一个阶段内部，如果单层太大，则通过张量并行（TP）在机器内部的多张卡上同时计算。
4. **Data Parallel 梯度聚合**：在整个训练步（Step）结束时，通过数据并行（DP）组将所有梯度的变化同步回所有计算单元，更新模型参数。

---

### （4） 3D 并行方案对比速查表

| 并行维度 | 切分方式 | 硬件与网络要求 | 主要解决的问题 | 典型应用框架 |
| --- | --- | --- | --- | --- |
| **张量并行 (TP)** | 矩阵内部切分 (Intra-layer) | **极高带宽**（必须在单机内使用 NVLink） | 单层参数量过大，单卡显存装不下 | Megatron-LM |
| **流水线并行 (PP)** | 按层垂直切分 (Inter-layer) | **中等带宽**（支持跨机/跨节点） | 模型总层数太多，单卡显存装不下 | Megatron-LM, DeepSpeed |
| **数据并行 / FSDP (DP)** | 优化器状态/参数分片 | **高带宽**（推荐 IB 网卡跨机互联） | 提升训练吞吐，分摊剩余显存冗余 | PyTorch FSDP, DeepSpeed |

在实际工程落地中，训练如 LLaMA-3 (70B/405B) 或 GPT-4 级别的模型，通常会根据集群规模（如几千张 H100）精确规划 3D 并行的组合比例（例如：$\text{TP}=8, \text{PP}=4, \text{DP}=X$），以达到硬件算力和通信带宽的最佳平衡。
