Gradient Accumulation in Mini-batch Training.py代码实现了一个基于 PyTorch 的图像分类训练循环，其中引入了梯度累积（Gradient Accumulation）技术。

梯度累积的核心思想是：**在显存有限、无法使用大 Batch Size 时，通过多次前向传播累积梯度，达到模拟“大批次训练”的效果。**

下面详细拆解这段代码：

---

### 一、 数据准备阶段

```python
# 数据预处理
transform = transforms.Compose([
    transforms.Resize((224, 224)),  # 将 CIFAR-10 的图片尺寸调整为 224x224
    transforms.ToTensor()           # 将图片转化为 Tensor，并将像素值归一化到 [0, 1]
])

# CIFAR-10数据集
train_dataset = datasets.CIFAR10(root="./data", train=True, download=True, transform=transform)
train_loader = DataLoader(train_dataset, batch_size=16, shuffle=True)  # 小批次训练

```

* **ResNet-18 的尺寸要求**：ResNet-18 是针对 ImageNet（224x224 分辨率）设计的主干网络。CIFAR-10 原图是 32x32 的，这里通过 `transforms.Resize((224, 224))` 放大到 224x224，使其能适配 ResNet。
* **小批次（Batch Size = 16）**：每次只让模型看 16 张图，显存占用很小。

---

### 二、 模型构建阶段

```python
# 使用ResNet-18模型（使用现代的 weights 参数替代已废弃的 pretrained）
model = models.resnet18(weights=models.ResNet18_Weights.DEFAULT)
model.fc = nn.Linear(model.fc.in_features, 10)  # CIFAR-10的10分类
model = model.cuda()

```

* **预训练权重**：`weights=models.ResNet18_Weights.DEFAULT` 加载了在 ImageNet 上训练好的特征提取权重，这能大幅加快收敛速度并提高准确率。
* **修改全连接层（`model.fc`）**：原版 ResNet-18 的最后一层全连接层输出是 1000 类（对应 ImageNet）。CIFAR-10 只有 10 个类别，因此通过 `nn.Linear(..., 10)` 将输出维度替换为 10。
* **移动到 GPU**：`.cuda()` 将模型加载到显卡上运行。

---

### 三、 核心：梯度累积的原理与实现

梯度累积的设置如下：

```python
accumulation_steps = 4  # 每4步累积更新一次

```

这意味着：**真正的 Batch Size = $16 \times 4 = 64$**。虽然代码里每次喂给显存的只有 16 张图，但模型参数每计算 4 个 Batch（即 64 张图）才真正更新一次。

代码中的训练循环细节拆解如下：

```python
for epoch in range(num_epochs):
    running_loss = 0.0
    optimizer.zero_grad()  # 修复 1：每个 Epoch 开始前清空一次梯度

    for i, (inputs, labels) in enumerate(train_loader):
        inputs, labels = inputs.cuda(), labels.cuda()

        # 1. 前向传播
        outputs = model(inputs)
        loss = criterion(outputs, labels)

        # 2. 核心：对 loss 进行缩放
        # 为什么要除以 accumulation_steps？
        # 因为 PyTorch 默认会把多次 backward() 的梯度进行【累加（Sum）】。
        # 如果不除以 4，累积 4 次后的梯度相当于真实梯度的 4 倍，会导致学习率过大、震荡甚至发散。
        loss = loss / accumulation_steps
        
        # 3. 反向传播，计算梯度并累加到 model.parameters().grad 中
        loss.backward()

        # 还原真实 loss 用于统计打印（因为上面除以了 4，这里要乘回来）
        running_loss += loss.item() * accumulation_steps  

        # 4. 判断是否触发参数更新
        is_accumulation_step = (i + 1) % accumulation_steps == 0
        is_last_batch = (i + 1) == total_batches

        if is_accumulation_step or is_last_batch:
            optimizer.step()     # 利用累积了 4 步的梯度来更新模型参数
            optimizer.zero_grad()  # 清空梯度，开启下一轮累积

```

#### 💡 关键细节剖析：

1. **为什么要对 `loss` 除以 `accumulation_steps`？**
在标准训练中，一个 Batch 的梯度是平均值。如果连续做 4 次前向+反向传播而不清空梯度，参数的 `.grad` 属性会把这 4 次的梯度**相加**。数学上，均值的和等于和的均值。为了让 4 个小批次合并起来的梯度等价于一个大批次（大小为 64）的平均梯度，必须在每次反向传播前将 `loss` 除以 `accumulation_steps`（即求平均）。
2. **处理“余数” Batch（`is_last_batch` 的作用）**：
如果总 Batch 数不能被 `accumulation_steps`（4）整除（例如总共有 1001 个 Batch），那么到最后剩下一个 Batch（第 1001 个）时，它只累积了 1 步就结束了循环。如果不加 `is_last_batch` 判断，这最后一步的梯度就会被丢弃，导致最后的数据没有参与参数更新。加上 `is_last_batch` 可以确保训练完最后一个不完整的组合时也能正常更新参数。
