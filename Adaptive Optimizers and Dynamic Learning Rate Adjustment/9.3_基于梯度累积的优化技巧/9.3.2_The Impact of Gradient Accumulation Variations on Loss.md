### 二、 固定随机种子与构造“有规律”的数据

```python
  # 1. 严格固定随机种子，确保每次实验初始权重和数据顺序完全一致
  torch.manual_seed(42)

  input_size, num_classes, num_samples = 10, 2, 1000
  # 2. 构造有真实规律的数据（线性可分+轻微噪声），而非纯随机噪声

  X = torch.randn(num_samples, input_size)
  logits = X @ true_weights + 0.5 * torch.randn(num_samples, 1)
  y = (logits.squeeze() > 0).long()

  dataloader = DataLoader(dataset, batch_size=32, shuffle=True)
```

### 三、 核心训练循环与梯度累积机制

```python
  model = SimpleModel(input_size, num_classes)
  criterion = nn.CrossEntropyLoss()
  optimizer = optim.Adam(model.parameters(), lr=0.01)

  for epoch in range(num_epochs):
    running_loss = 0.0
    optimizer.zero_grad()  # 每个 Epoch 开始前清空梯度

    for i, (inputs, labels) in enumerate(dataloader):
      outputs = model(inputs)
      raw_loss = criterion(outputs, labels)

      # 3. 累加真实未缩放的 loss 用于准确统计
      running_loss += raw_loss.item()

      # 缩放 loss 进行反向传播
      loss = raw_loss / accumulation_steps
      loss.backward()

      # 达到累积步数时更新参数
      if (i + 1) % accumulation_steps == 0:
        optimizer.step()
        optimizer.zero_grad()

```

1. **真实 Loss 的统计**：代码用 `raw_loss.item()` 累加未经缩放的原始损失，保证了打印出来的 `Real Loss` 在所有对比实验中具有相同的衡量标准，不会因为除以了 `accumulation_steps` 而产生虚假的视觉下降。
2. **损失缩放（Loss Scaling）**：`loss = raw_loss / accumulation_steps`。因为 PyTorch 的 `backward()` 是累加语义（`+=`），必须先将 Loss 缩小 $K$ 倍，累加 $K$ 次后，其等效梯度才等于一个完整大批次的平均梯度。
3. **参数更新触发**：每当迭代次数满足 `(i + 1) % accumulation_steps == 0` 时，调用 `optimizer.step()` 更新模型权重，并用 `optimizer.zero_grad()` 清空累积的梯度。

### 四、 残余梯度兜底与指标计算

```python
    # 4. 处理无法整除时的残余梯度
    if len(dataloader) % accumulation_steps != 0:
      optimizer.step()
      optimizer.zero_grad()

    print(
        f"Epoch [{epoch + 1:2d}/{num_epochs}], Real Loss:"
```

1. **兜底更新**：`num_samples = 1000` 且 `batch_size = 32` 时，一共有 32 个 Batch（$1000 / 32 = 31.25 \rightarrow 32$）。如果 `accumulation_steps = 3` 或 `5` 无法被 32 整除，Epoch 结束时会留下一部分残余梯度。这段 `if` 逻辑确保了残余梯度被正确提交更新，避免数据浪费和污染下一个 Epoch。
2. **Epoch 平均 Loss 打印**：`running_loss / len(dataloader)` 计算并打印出了当前 Epoch 中所有样本的平均交叉熵损失，清晰直观地展示了训练收敛的过程。

观察实验结果，会发现一个非常鲜明的规律：**随着 `accumulation_steps` 增大（等效 Batch Size 从 32 增加到 256），每个 Epoch 结束时的 `Real Loss` 下降速度越来越慢。**

例如，在第 10 个 Epoch：

* `steps = 1` 时，Loss 降到了 **0.1773**
* `steps = 8` 时，Loss 却停留在 **0.4376**

这并不是说梯度累积算法本身有问题，而是由实验设计中的两个核心机制（更新频率与学习率匹配）共同决定的。具体原因可以从以下三个维度来解释：

---

#### 1. 最核心原因：参数更新总次数的悬殊差距（Update Frequency）

在代码中，数据集总共有 1000 个样本，`batch_size = 32`，因此一个 Epoch 包含 **32 个 Batch**（$1000 / 32 = 31.25$，向上取整为 32 个数据批次）。

当设置不同的 `accumulation_steps` 时，**优化器在一个 Epoch 内实际执行 `.step()`（参数更新）的次数**发生了剧烈变化：

* **`steps = 1`**：每个 Batch 更新一次 $\rightarrow$ 每个 Epoch 更新 **32 次** $\rightarrow$ 10 个 Epoch 共更新 **320 次**。
* **`steps = 2`**：每 2 个 Batch 更新一次 $\rightarrow$ 每个 Epoch 更新 **16 次** $\rightarrow$ 10 个 Epoch 共更新 **160 次**。
* **`steps = 4`**：每 4 个 Batch 更新一次 $\rightarrow$ 每个 Epoch 更新 **8 次** $\rightarrow$ 10 个 Epoch 共更新 **80 次**。
* **`steps = 8`**：每 8 个 Batch 更新一次 $\rightarrow$ 每个 Epoch 更新 **4 次** $\rightarrow$ 10 个 Epoch 共更新 **40 次**。

**结论**：在相同的 Epoch 数（10个）下，`steps = 8` 的模型总共只被“调教”了 40 次，而 `steps = 1` 的模型被调教了 320 次。更新次数少了 8 倍，模型学到的有效信息自然少得多，Loss 下降慢是完全符合逻辑的。

---

#### 2. 关键诱因：未对大批量进行“学习率缩放”（Learning Rate Mismatch）

在深度学习优化理论中，有一个著名的**线性缩放规则（Linear Scaling Rule）**：

> **当 Batch Size（或等效的梯度累积步数）扩大 $K$ 倍时，学习率（LR）通常也需要放大 $K$ 倍**，才能维持相似的参数更新步幅。

* 在实验中，无论 `accumulation_steps` 是 1 还是 8，**学习率始终固定在 `lr = 0.01**`。
* 当 `steps = 8` 时，等效 Batch Size 扩大到了 256。这意味着模型收集了 8 倍的数据才敢“挪动一步”，但这一步的步长（学习率）却和以前一样大。由于大批量的梯度方向更加平稳、平均，固定的小学习率导致它每次更新迈出的步伐太保守，从而导致收敛极其缓慢。

---

#### 3. 大批量优化固有的收敛特性（Loss Landscape Dynamics）

除了上述两个工程与超参数层面的原因外，大批量（Large Batch Size）在数学本质上也有其特点：

* **小批量（如 `steps = 1`）**：梯度带有较强的随机噪声（Stochastic Noise）。这种“噪声”虽然有时会引起 Loss 波动，但它能帮助模型像“醉汉走路”一样，更容易跳出某些浅层的局部最优解，初期下降速度极快。
* **大批量（如 `steps = 8`）**：梯度估计更加精确平稳，但由于缺乏随机噪声的“推力”，它在优化时的动态路径往往更平缓、保守，在早期需要更多的迭代步数才能显现出优势。

---

#### 总结与验证思路

如果希望在控制变量（保证优化器实际更新次数相同）的前提下公平对比梯度累积的效果，应该：

1. **按总更新步数（Steps）而不是 Epoch 数来衡量**：例如让 `steps = 8` 跑更多的 Epoch，使它们的总更新次数对齐。
2. **应用线性学习率缩放**：当 `accumulation_steps = K` 时，将 `lr` 同步放大 $K$ 倍（例如 `lr = 0.01 * K`）。你会发现，缩放学习率后，大批量的收敛轨迹会与小批量高度吻合。
