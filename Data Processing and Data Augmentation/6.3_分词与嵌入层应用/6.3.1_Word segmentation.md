Word segmentation.py代码实现了一个教育级的 **BPE（Byte-Pair Encoding，字节对编码）分词器**。它的核心目的通过纯 Python 代码展示现代大模型（如 GPT 系列）在底层是如何通过统计学方法将文本逐步合并为子词（Subword）词表的。

下面对代码的整体架构和各个核心函数进行详细拆解。

---

### 一、 整体工作流程概述

BPE 是一种**自底向上**的子词词表构建算法：

1. **初始化**：将语料库中的每个词拆分为单字符序列（例如将“自然”拆分为 `自 然`），并统计每个序列在语料中出现的频次。
2. **统计频率**：扫描当前词表中所有相邻的字符对（Bigram），计算它们的出现总频次。
3. **合并最高频对**：找到频次最高的一组相邻字符，将它们合并为一个新的单一符号。
4. **迭代循环**：重复步骤 2 和 3，直到达到预设的合并次数（`num_merges`）或词表大小限制。

---

### 二、 核心函数详解

#### 1. 数据初始化：`get_vocab(texts)`

```python
def get_vocab(texts):
    vocab = {}
    for text in texts:
        # 将文本转换为以空格分隔的字符序列作为字典的键，初始频次为 1
        word = ' '.join(list(text))
        vocab[word] = vocab.get(word, 0) + 1
    return vocab

```

* **功能**：将输入的文本行转化为 BPE 的初始词表。
* **机制**：
* `list(text)` 把每行文本切分为单个字符（对于中文来说，就是把每个汉字、标点拆开）。
* `' '.join(...)` 在字符之间插入空格（例如 `"自然"` 变为 `"自 然"`），这是为了让后续的正则和分割能够清晰识别边界。
* `vocab` 字典的**键**是带空格的字符序列字符串，**值**是该序列在文本中出现的频次。



#### 2. 统计相邻字符对：`get_stats(vocab)`

```python
def get_stats(vocab):
    pairs = defaultdict(int)
    for word, freq in vocab.items():
        symbols = word.split()
        for i in range(len(symbols) - 1):
            pairs[symbols[i], symbols[i + 1]] += freq
    return pairs

```

* **功能**：统计当前词表中所有相邻字符对（Bigram）的加权频次。
* **机制**：
* 遍历词表中的每个“词”（即带空格的字符串），用 `.split()` 还原成独立的符号列表 `symbols`。
* 通过双循环提取所有相邻的二元组 `(symbols[i], symbols[i + 1])`。
* 将该二元组的频次累加（乘以该词在语料中出现的总频次 `freq`）。例如，如果 `"自 然"` 出现了 3 次，那么 `('自', '然')` 的频次就会增加 3。



#### 3. 执行合并：`merge_vocab(vocab, pair)`

```python
def merge_vocab(vocab, pair):
    new_vocab = {}
    bigram = re.escape(' '.join(pair))
    p = re.compile(r'(?<!\S)' + bigram + r'(?!\S)')
    for word in vocab:
        w_out = p.sub(''.join(pair), word)
        new_vocab[w_out] = vocab[word]
    return new_vocab

```

* **功能**：在整个词表中，把出现频率最高的那对相邻字符合并为一个新符号。
* **技术亮点（正则边界控制）**：
* `re.escape(' '.join(pair))`：将待合并的字符对（如 `('自', '然')`）转义为正则安全的字符串 `"自 然"`。
* `r'(?<!\S)'` 和 `r'(?!\S)'`：这是 **零宽断言（Lookbehind & Lookahead）**，用于确保匹配的字符对前后是空白字符或字符串边界。
* **为什么要加边界限制？** 假设我们要把 `a` 和 `b` 合并为 `ab`，如果没有边界限制，单词中不相干的子串也可能会被误伤。加上边界后，它确保只匹配独立的子词对，避免部分匹配带来的结构混乱。
* `p.sub(''.join(pair), word)`：将匹配到的带空格字符对合并（例如将 `"自 然"` 替换为 `"自然"`），生成更新后的词表键。



#### 4. 主控函数：`bpe_tokenize(texts, num_merges)`

```python
def bpe_tokenize(texts, num_merges):
    vocab = get_vocab(texts)
    for i in range(num_merges):
        pairs = get_stats(vocab)
        if not pairs:
            break
        best = max(pairs, key=pairs.get)
        vocab = merge_vocab(vocab, best)
    return vocab

```

* **功能**：控制整个 BPE 训练的迭代过程。
* **流程**：
1. 调用 `get_vocab` 初始化词表。
2. 进入 `num_merges` 次循环（代表我们要进行多少轮合并）：
* 调用 `get_stats` 获取当前所有字对的频率。
* 如果没有可统计的字对（`pairs` 为空），提前退出。
* 用 `max(pairs, key=pairs.get)` 挑出频率最高（`freq` 最大）的那一对 `best`。
* 调用 `merge_vocab` 在词表中执行合并。


3. 返回训练完成后的最终词表。

### 四、 总结与局限性

* **这段代码的价值**：它用不到 40 行的纯 Python 代码，完美复现了大模型分词器（如 GPT 采用的 BPE 核心逻辑）的数学本质：**从字（Character）出发，基于统计频率不断向上聚合成子词（Subword）**。
* **与生产环境（如 Hugging Face Tokenizers / SentencePiece）的区别**：
* 真实的大模型分词器处理的是字节（Bytes）而不是单纯的 Unicode 字符，以支持多语言和防止乱码。
* 真实分词器会使用更底层的 C++ 实现（如 Rust 写的 `tokenizers` 库），并支持预分词（Pre-tokenization，例如按标点和空格先切分）、特殊标记（如 `[PAD]`, `<|endoftext|>`）以及高效的 Trie 树加速。
