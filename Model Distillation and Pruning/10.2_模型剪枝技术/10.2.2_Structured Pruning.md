Structured Pruning.py代码展示了真正的结构化剪枝（True Structured Pruning）在工程落地时的核心逻辑：**通过直接缩小网络层的维度（Shape），实现物理参数量的真正下降与推理时间的实际缩短**。

下面进行逐模块的详细拆解：

---

### 一、 核心模块详解

#### 1. 动态可配置的网络结构 (`SimpleNN` 类)

```python
class SimpleNN(nn.Module):
    def __init__(self, h1=256, h2=128):
        super(SimpleNN, self).__init__()
        self.fc1 = nn.Linear(784, h1)  # 第一层输入 784，输出 h1
        self.relu = nn.ReLU()
        self.fc2 = nn.Linear(h1, h2)   # 第二层输入 h1，输出 h2
        self.fc3 = nn.Linear(h2, 10)   # 第三层输入 h2，输出 10 (分类数)

```

* **设计意图**：传统的固定层定义不利于对比。这里将隐藏层的神经元数量（`h1` 和 `h2`）设计为可传入的参数。
* **剪枝模拟**：在实际工程中，结构化剪枝算法（如基于通道重要性评分）会计算出哪些神经元或通道最不重要并将其剔除。代码中通过“重新实例化一个更小维度的模型（`h1=128, h2=64`）”，完美等效模拟了当剪掉 50% 的通道后，网络结构在内存中物理缩小的状态。

#### 2. 物理参数量统计函数 (`count_parameters`)

```python
def count_parameters(model):
    return sum(p.numel() for p in model.parameters() if p.requires_grad)

```

* **工作原理**：遍历模型中所有可训练的参数（权重矩阵 `weight` 和偏置 `bias`），使用 `p.numel()`（Number of elements）计算出每个张量包含的元素总数并求和。
* **为什么有效**：由于这次我们改变了 `nn.Linear` 的输入输出矩阵形状（例如从 $256 \times 784$ 变成 $128 \times 784$），矩阵的物理尺寸变小了，因此该函数统计出来的参数总量会**成倍下降**。

#### 3. 严谨的推理性能基准测试 (`benchmark`)

```python
def benchmark(model, inputs):
    model.eval()
    with torch.no_grad():
        for _ in range(10): _ = model(inputs) # 预热 (Warm-up)
        start = time.time()
        for _ in range(100): 
            _ = model(inputs)
        return (time.time() - start) * 10  # 测算 100 次的平均耗时

```

* **性能测试的严谨性**：
* **`model.eval()`**：关闭 Dropout 和 BatchNorm 等训练期特有行为，确保推理路径确定。
* **`torch.no_grad()`**：关闭梯度计算，节省显存并还原真实的前向推理性能。
* **预热循环 (Warm-up)**：GPU/CPU 在初次执行计算时往往需要进行缓存分配和内核加载（JIT 编译等），预热可以排除冷启动对计时结果的干扰。
* **多次循环取均值**：通过连续运行 100 次并计算耗时，极大减小了操作系统调度带来的随机误差。

### 二、 为什么这段代码能体现出“质”的飞跃？

对比前文使用的 PyTorch 原生 `prune` 模块（它采用的是**掩码机制 Mask**，矩阵物理形状不变、计算量不变），这段代码代表了工业界进行**模型部署加速**的真实方向：

1. **计算复杂度（FLOPs）的真正减少**：
* 原始模型的第一层矩阵乘法计算量为 $784 \times 256$，裁剪后变为 $784 \times 128$，乘法运算量直接减半。


2. **内存带宽（Memory Bandwidth）的优化**：
* 现代深度学习推理很多时候受限于内存带宽（Memory Bound）。更小的权重矩阵占用的显存/内存更少，缓存命中率更高，从而使推理耗时（毫秒数）真正缩短。
