Greedy_Beam_Search.py这段代码在前面实现的 **GPT-2 基础架构**（自注意力、Pre-LN、GELU 激活等）之上，重点扩展实现了两种经典的自回归文本解码算法：**贪婪搜索（Greedy Search）** 和 **集束搜索（Beam Search）**。

下面详细拆解新增和修改的代码逻辑。

---

### 一、 核心修改点概览

1. **`GPT2TextGenerator` 移除原先杂糅的 `generate` 方法**，拆分成了两个独立且职责分明的解码函数：
* `greedy_search()`：实现贪婪解码。
* `beam_search()`：实现多路径集束搜索。


2. **测试脚本（`if __name__ == "__main__":`）**：增加了 `eos_id` 结束符，并分别调用了这两种搜索算法进行推理测试。

---

### 二、 核心解码函数详细解析

#### 1. `greedy_search`（贪婪搜索实现）

* **思想**：每一步只选择概率最高的那一个词。
* **核心代码逻辑**：
```python
x = torch.tensor([generated], device=next(self.parameters()).device)
logits = self.forward(x)
# 取最后一个时间步的 logits，并通过 argmax 选出概率最大的词 ID
next_token = torch.argmax(logits[:, -1, :], dim=-1).item()

```


* **退出机制**：
* 达到指定的 `max_len` 最大长度。
* 生成的词等于结束符 `eos_token_id` 时提前终止（`break`）。



#### 2. `beam_search`（束搜索实现）

* **思想**：维护一个大小为 `beam_width`（这里设为 3）的候选池，通过多路并行搜索寻找累积概率最高的全局序列。
* **执行步骤拆解**：
1. **初始化**：
```python
beams = [(list(start_token), 0.0)]  # 候选池：存储 (序列列表, 累计对数概率)
completed_beams = []  # 存储已经遇到 EOS 结束符的候选序列

```


2. **循环迭代（Token by Token）**：
* 对于当前候选池中的每一个序列，先检查它是否已经结束（如果最后一个词是 `eos_token_id`，则放入 `completed_beams`，不再展开）。
* 如果没结束，将其输入模型前向传播，获取最后一个时间步的输出，并用 **`F.log_softmax`** 将 Logits 转换为**对数概率（Log Probabilities）**。
> *为什么要用对数概率？* 概率相乘在数值计算中容易下溢（接近于 0），转换为对数后，连乘变成了**连加**（`score + top_k_log_prob`），计算更稳定。


* 使用 **`torch.topk(..., beam_width)`** 选出当前步概率最高的前 $K$ 个词。
* 将这 $K$ 个扩展后的新序列及其更新后的分数存入 `all_candidates`。


3. **剪枝与筛选**：
* 从所有候选组合中，按分数从高到低排序（`reverse=True`）。
* 截取前 `beam_width` 个最优候选更新 `beams`。
* 代码中包含了一句调试打印：`print(f"当前轮次保留的 {beam_width} 条路径：", ...)`，方便观察每一步 Beam 的演化过程。


4. **最终后处理与长度惩罚（Length Normalization）**：
```python
all_final = completed_beams + beams
best_seq = max(all_final, key=lambda x: x[1] / len(x[0]))[0]

```


* **为什么要做除以 `len(x[0])` 的长度归一化？**
对数概率都是负数，累加的词越多分数越低。如果不做归一化，Beam Search 会天然偏向生成极短的句子。通过除以序列长度（计算平均对数概率），可以平衡长短句子的竞争。
