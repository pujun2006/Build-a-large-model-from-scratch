Adapter_Tuning.py这份代码实现了一个完整的、符合标准规范的 **BERT 适配器微调（Adapter Tuning）** 流程。它在冻结 BERT 原生主干网络参数的前提下，通过在每一层 Transformer 后面插入轻量级瓶颈结构（Adapter）并外接分类头，实现了高效的参数微调。

以下是对该段最终代码的**详细核心模块拆解与运行机制说明**：

---

### 一、 代码架构总览

整个脚本可以分为 6 个核心部分：

1. **Adapter 模块定义**：轻量级的降维-升维非线性瓶颈结构。
2. **带 Adapter 的 BERT 模型**：冻结 BERT 主干，注入多层 Adapter 并外接分类头。
3. **分词器加载**：将文本转化为 Transformer 可处理的数字 ID。
4. **数据准备**：构造微型文本数据集和 DataLoader。
5. **优化器与组件配置**：指定只更新 Adapter 和分类头的参数。
6. **训练主循环**：执行前向传播、计算损失、反向传播与参数更新。

### 二、 核心代码逐模块深度解析

#### 1. Adapter 模块（第 8-20 行）

```python
class Adapter(nn.Module):
    def __init__(self, input_dim, bottleneck_dim=64):
        super(Adapter, self).__init__()
        self.down_project = nn.Linear(input_dim, bottleneck_dim) # 降维 (768 -> 64)
        self.activation = nn.ReLU()                              # 激活函数
        self.up_project = nn.Linear(bottleneck_dim, input_dim)   # 升维 (64 -> 768)

    def forward(self, x):
        x_down = self.down_project(x)
        x_activated = self.activation(x_down)
        x_up = self.up_project(x_activated)
        return x + x_up  # 残差连接 (Residual Connection)

```

* **瓶颈设计**：BERT-base 的隐藏层维度是 768。Adapter 先将其压缩到 64 维（`bottleneck_dim`），提取核心特征后再恢复到 768 维。这使得需要训练的参数量骤降，极其省显存。
* **残差连接**：`return x + x_up` 保证了在训练刚开始时（Adapter 权重接近 0），输入信息可以无损通过，不会破坏 BERT 原本已经学习到的强大语义表示，极大提升了模型训练的稳定性。

#### 2. 带有 Adapter 和分类头的 BERT 模型（第 23-52 行）

```python
class BertWithAdapter(nn.Module):
    def __init__(self, adapter_dim=64, num_classes=2):
        super(BertWithAdapter, self).__init__()
        self.bert = BertModel.from_pretrained("bert-base-uncased")
        
        # 【关键】冻结 BERT 原有参数，不参与梯度更新
        for param in self.bert.parameters():
            param.requires_grad = False

        # 为 BERT 的 12 层 Transformer 分别创建一个对应的 Adapter 模块
        self.adapters = nn.ModuleList(
            [Adapter(self.bert.config.hidden_size, adapter_dim) for _ in range(self.bert.config.num_hidden_layers)]
        )
        
        # 新增分类头：将最终的 768 维 [CLS] 特征映射到分类结果（2类）
        self.classifier = nn.Linear(self.bert.config.hidden_size, num_classes)

    def forward(self, input_ids, attention_mask):
        # 开启 output_hidden_states=True，获取每一层的输出
        outputs = self.bert(input_ids=input_ids, attention_mask=attention_mask, output_hidden_states=True)
        hidden_states = list(outputs.hidden_states) # 包含 1 个 embedding 输出 + 12 个层输出

        # 逐层注入 Adapter 修正
        for i in range(len(self.adapters)):
            delta = self.adapters[i](hidden_states[i + 1])
            hidden_states[i + 1] = hidden_states[i + 1] + delta

        # 取出最后一层中 [CLS] 标记（位置 0）对应的向量，形状: [batch_size, 768]
        cls_output = hidden_states[-1][:, 0, :]
        
        # 通过分类头得到最终 logits，形状: [batch_size, 2]
        logits = self.classifier(cls_output)
        return logits

```

* **参数冻结机制**：`param.requires_grad = False` 锁死了原版 BERT 的所有亿级参数，只让新加的组件产生梯度，这是参数高效微调（PEFT）的灵魂。
* **隐状态拦截与修正**：通过复用 BERT 官方的高效前向传播并抓取中间各层状态（`outputs.hidden_states`），以列表形式在每一层输出后外接了 Adapter 残差，完美规避了底层张量维度冲突。

#### 3. 数据处理与加载（第 55-68 行）

```python
def prepare_data(texts, labels, tokenizer, max_length=128):
    encodings = tokenizer(texts, truncation=True, padding=True, max_length=max_length, return_tensors="pt")
    input_ids, attention_mask = encodings["input_ids"], encodings["attention_mask"]
    labels = torch.tensor(labels)
    return TensorDataset(input_ids, attention_mask, labels)

texts = ["The model is effective for tuning.", "Adapters enable efficient fine-tuning."]
labels = [1, 0]
dataset = prepare_data(texts, labels, tokenizer)
dataloader = DataLoader(dataset, batch_size=2)

```

* 利用 `BertTokenizer` 将文本统一截断并填充（padding）到相同长度，转换为 PyTorch 张量，最后打包为 `TensorDataset` 和支持批次训练的 `DataLoader`。

#### 4. 优化器和训练组件（第 71-82 行）

```python
model = BertWithAdapter(adapter_dim=64, num_classes=2)

# 精准控制：只优化 adapter 参数 和 分类头 (classifier) 参数
optimizer = optim.Adam(
    list(model.adapters.parameters()) + list(model.classifier.parameters()), 
    lr=1e-4
)
criterion = nn.CrossEntropyLoss()

device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
model.to(device)

```

* **参数白名单机制**：`optimizer` 的参数列表只传入了 `model.adapters.parameters()` 和 `model.classifier.parameters()`。由于 BERT 主干网络未被传入，因此在执行 `loss.backward()` 和 `optimizer.step()` 时，只有 Adapter 和分类头会被更新。

#### 5. 单轮训练函数与执行（第 85-115 行）

```python
def train_one_epoch(dataloader, model, criterion, optimizer):
    model.train()
    total_loss, correct_predictions = 0, 0

    for batch in dataloader:
        input_ids, attention_mask, labels = [x.to(device) for x in batch]

        # 1. 前向传播
        logits = model(input_ids=input_ids, attention_mask=attention_mask)

        # 2. 计算交叉熵损失
        loss = criterion(logits, labels)

        # 3. 反向传播与梯度优化
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()

        # 4. 统计指标
        total_loss += loss.item()
        _, preds = torch.max(logits, dim=1)
        correct_predictions += torch.sum(preds == labels).item()

    avg_loss = total_loss / len(dataloader)
    accuracy = correct_predictions / len(dataloader.dataset)
    return avg_loss, accuracy

# 迭代 3 个 Epoch 进行训练
for epoch in range(3):
    avg_loss, accuracy = train_one_epoch(dataloader, model, criterion, optimizer)
    print(f"Epoch {epoch + 1} Loss: {avg_loss:.4f}, Accuracy: {accuracy:.4f}")

```

* 标准的 PyTorch 训练三部曲（清空梯度 `zero_grad` $\rightarrow$ 反向传播 `backward` $\rightarrow$ 参数更新 `step`），并在每个 Batch 中计算预测准确率（通过 `torch.max` 选出概率最大的类别索引与真实标签对比）。

不过，从模型训练的实际效果来看，这个结果呈现出的 **`Accuracy: 0.5000`（50%）** 和 **Loss 波动** 是由以下几个特定原因导致的：

#### 1. 为什么准确率一直是 50%？

* **数据集极小**：你的代码中只准备了 **2 条示例数据**（`labels = [1, 0]`），并且设置的 `batch_size = 2`。这意味着每个 Epoch 里**只有 1 个 Batch**。
* **准确率的数学本质**：在这仅有的 2 条数据中，模型预测对了一条、预测错了另一条（或者全猜对了同一个类别），正确数就是 1 / 2 = **0.5（50%）**。在二分类任务中，50% 的准确率就相当于**随机盲猜**。

#### 2. 为什么 Loss 没有稳步下降？

Loss 在在几轮中出现了上下波动（0.9099 $\rightarrow$ 0.7829 $\rightarrow$ 0.8880）：

* **缺乏足够的统计意义**：2 条样本无法提供稳定的梯度方向。每次更新参数时，模型都在为这两条截然相反的文本（一条标签是 1，一条是 0）硬调参数，导致优化器在两个极端的方向拉扯，Loss 自然无法平稳收敛。
* **冷启动的分类头**：虽然 Adapter 在工作，但新增的分类头（Classifier）是随机初始化的，需要更多的数据和轮次来建立决策边界。
