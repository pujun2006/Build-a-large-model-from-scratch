**Prompt Tuning**（提示微调）是大语言模型参数高效微调（PEFT, Parameter-Efficient Fine-Tuning）家族中的经典方法之一，由 Google 团队在 2021 年的论文《The Power of Scale for Parameter-Efficient Fine-Tuning》中提出。

与全量微调（Full Fine-Tuning）动辄更新所有模型参数不同，Prompt Tuning 的核心思想是：**冻结预训练语言模型的所有原始参数，仅在输入嵌入（Input Embedding）层前拼接一小段可学习的连续型向量（称为 Soft Prompt / 虚拟 Token），并通过反向传播仅优化这些虚拟 Token 的参数。**

---

## 一、 核心原理

### 1. 硬提示（Hard Prompt）与软提示（Soft Prompt）

* **硬提示（Discrete / Hard Prompt）：** 人工设计的自然语言文本，例如 `"请将以下英文翻译成中文："`。它们对应词表中的离散 Token ID，无法直接计算梯度进行优化。
* **软提示（Continuous / Soft Prompt）：** 一组直接在模型嵌入空间中定义的连续向量参数。它们不对应任何具体的自然语言词汇，但可以作为虚拟 Token 参与模型的自注意力计算。

### 2. 数学建模与前向传播

设预训练模型的嵌入层为 $E: \mathcal{V} \to \mathbb{R}^{d}$（其中 $\mathcal{V}$ 为词表， $d$ 为隐藏层维度）。

1. 对于输入文本序列，其 Token ID 为 $X = [x_1, x_2, \dots, x_s]$，经过词表嵌入后得到输入特征：

$$E(X) \in \mathbb{R}^{b \times s \times d}$$



其中 $b$ 为 Batch Size，$s$ 为序列长度。
2. 定义一组可学习的软提示参数矩阵：

$$P \in \mathbb{R}^{l \times d}$$



其中 $l$ 为虚拟 Token 的长度（通常为 10 到 100 左右）。
3. 在 Batch 维度上将 $P$ 扩展并拼接在输入特征的左侧，得到最终送入 Transformer 层的混合输入序列 $\tilde{E}$：

$$\tilde{E} = \left[ \text{Broadcast}(P, b) \,;\, E(X) \right] \in \mathbb{R}^{b \times (l + s) \times d}$$


4. 模型在冻结主干网络（Transformer Blocks & LM Head）权重的前提下，仅通过计算任务损失（Loss）并将梯度回传至参数矩阵 $P$，从而实现特定下游任务的适配。

### 3. 与其他 PEFT 方法的本质区别

* **vs. Prefix Tuning：** Prefix Tuning 在模型的**每一层**的 Key 和 Value 矩阵前都拼接可训练的前缀向量；而 Prompt Tuning **仅在输入层**拼接，结构更加轻量，对底层架构侵入性极小。
* **vs. LoRA：** LoRA 通过在权重矩阵旁引入低秩分解矩阵来修改注意力权重；Prompt Tuning 则完全不改动模型权重，仅通过控制输入空间来引导模型行为。

## 二、 关键工程设计与实现考量

在将 Prompt Tuning 落地到实际大模型训练时，有几个关键的工程细节需要处理：

1. **参数初始化策略（Initialization）：**
* **随机初始化：** 使用正态分布（如 $\mathcal{N}(0, 0.02)$）对虚拟 Prompt 矩阵进行随机初始化。
* **词表初始化（Prompt Initialization）：** 从模型的预训练词表中挑选高频词、任务相关的代表性词汇（如分类任务的标签词）的 Embedding 来初始化 $P$。研究表明，词表初始化能显著加快模型的训练收敛速度，并提升最终性能。


2. **注意力掩码（Attention Mask）同步调整：**
由于在文本嵌入前拼接了长度为 $l$ 的虚拟 Token，输入序列的总长度变成了 $l + s$。因此，对应的 `attention_mask` 也必须在左侧拼接相同长度的全 `1` 掩码（形状为 `[Batch_Size, l]`），以确保模型在自注意力计算时能够正常关注到这些虚拟 Token。
3. **位置编码（Position IDs）：**
根据模型使用的是绝对位置编码还是相对位置编码（如 RoPE），需要对位置索引进行对应调整（例如将虚拟 Token 的位置索引设为 `0` 到 `l-1`，后续文本顺延），防止位置信息错乱。

## 三、 Prompt Tuning 的优缺点分析

### 优势

1. **极高的参数效率：** 可训练参数量极小（通常仅占全模型参数的 0.01% - 0.1%）。例如对于一个 170B 的大模型，仅需训练几万个参数。
2. **存储与部署成本低：** 基础大模型权重完全冻结且只需加载一份。不同的下游任务只需要保存各自几百 KB 的 Prompt 权重文件（向量矩阵），在多租户服务中切换任务开销极低。
3. **随着模型规模增大，性能趋近全量微调：** 论文证明，当模型参数量达到百亿级别（如 10B+）时，Prompt Tuning 的性能表现可以媲美甚至赶上全量微调。

### 劣势与局限性

1. **小模型表现不佳：** 在参数量较小（如小于 1B）的模型上，Prompt Tuning 的效果显著逊色于全量微调或 LoRA。
2. **收敛速度较慢：** 由于优化空间受限，通常需要更多的训练轮次（Epochs）才能收敛。
3. **可解释性差：** 软提示是纯粹的连续向量，无法像硬提示那样直观地通过文字进行人工干预或审计。
