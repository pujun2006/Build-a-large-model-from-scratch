Fine-tuning and Validation of Sentiment Models for Long-form Text.py这段代码实现了一个基于 **P-Tuning**（Prompt Tuning 的改进版，使用 LSTM + MLP 编码器）的 **BERT 文本分类模型**。它属于参数高效微调（Parameter-Efficient Fine-Tuning, PEFT）技术的一种，通过在输入文本前拼接可训练的“连续提示（Continuous Prompts）”，在冻结 BERT 主体参数的情况下，仅训练少量的 Prompt 编码器参数即可完成微调。

下面为你分模块详细解析这段代码的核心逻辑：

---

## 1. P-Tuning 编码器模块 (`PTuningEncoder`)

P-Tuning 的核心思想是将离散的 Prompt 模板（如“这是一个[MASK]句子”）替换为**可连续优化的向量（Embedding）**。为了解决直接优化独立 Embedding 容易导致训练不稳定、难以收敛的问题，代码中引入了一个 **LSTM + MLP 编码器**来生成这些 Prompt 嵌入。

* **`self.embedding`**: 为每个 Prompt 位置（长度为 `prompt_length`）初始化一个基础的离散索引，并映射到隐藏层维度 `embed_dim`。
* **`self.lstm`**: 使用一个 **双向 LSTM (Bidirectional LSTM)**，共 2 层。双向 LSTM 能够捕捉 Prompt 词之间的前后上下文依赖关系，增强 Prompt 向量的表达能力。输出维度会变成 `embed_dim * 2`。
* **`self.mlp`**: 一个多层感知机（Linear -> ReLU -> Linear），将双向 LSTM 的输出维度从 `embed_dim * 2` 映射回 BERT 所需的隐藏层维度 `embed_dim`。
* **`forward` 过程**:
1. 生成一个长度为 `prompt_length` 的自增张量作为输入索引。
2. 通过 Embedding 层和 LSTM，再经过 MLP，最终输出形状为 `(batch_size, prompt_length, embed_dim)` 的连续 Prompt 嵌入向量。



---

## 2. 集成模型定义 (`BertWithPTuningCorrected`)

这个类将 BERT 分类模型与 P-Tuning 编码器结合起来，负责在模型的输入层（Embedding 层）拼接 Prompt 和真实文本。

* **`forward` 核心步骤**:
1. **获取文本 Embedding**: 调用 `self.bert.get_input_embeddings()(input_ids)` 将输入的文本 `input_ids` 转换为标准的 BERT 词嵌入。
2. **生成 Prompt 嵌入**: 调用 `PTuningEncoder` 生成当前 batch 的 Prompt 嵌入 `prompt_embeds`。
3. **拼接（Concatenation）**: 使用 `torch.cat((prompt_embeds, inputs_embeds), dim=1)` 在序列长度维度（`dim=1`）上，把 Prompt 放在文本的最前面。
4. **扩展注意力掩码（Attention Mask）**: 原来的 `attention_mask` 只对应文本部分。由于前面多了 `prompt_length` 长度的 Prompt，必须在左侧补全相同长度的 `1`（表示这些 Prompt 参与注意力计算），形成 `extended_attention_mask`。
5. **输入 BERT**: 将拼接好的 `inputs_embeds` 和扩展后的 `extended_attention_mask` 传入 BERT 模型。如果传了 `labels`，Hugging Face 的 `BertForSequenceClassification` 会自动计算交叉熵损失（Loss）。



---

## 3. 主程序：加载、训练与测试 (`if __name__ == "__main__":`)

这部分展示了完整的训练与推理流程：

### (1) 模型与分词器初始化

加载 `bert-base-uncased`，创建分类模型（`num_labels=2`），并实例化自定义的 `BertWithPTuningCorrected`（设置 `prompt_length = 10`）。

### (2) 长度控制

代码中有一行对最大长度的处理：

```python
max_len = 512 - prompt_length

```

这是为了防止 `(文本长度 + 提示词长度)` 超过 BERT 允许的最大序列长度（通常为 512），从而避免触发位置编码溢出错误。

### (3) 参数冻结（冻结主体，只训 Prompt）

```python
for param in tuned_model.bert.parameters():
  param.requires_grad = False

```

* **这是 P-Tuning 的精髓**：将 BERT 主体的所有参数设为不可训练（`requires_grad = False`）。
* 优化器只传入 `tuned_model.ptuning_encoder.parameters()`，这意味着在反向传播时，**只有 LSTM 和 MLP 的参数会被更新**，从而极大地节省了显存并减少了训练参数量。

### (4) 训练循环

* 使用 `AdamW` 优化器，学习率设为 `1e-3`（相比微调整个 BERT 通常需要的 `2e-5`，P-Tuning 的学习率通常可以设得更大）。
* 进行了 10 个 Epoch 的简单训练，每个 Epoch 打印出当前 Loss。

### (5) 推理与评估

* 训练结束后，切换至 `tuned_model.eval()`。
* 在 `torch.no_grad()` 下进行前向传播（不传 `labels`），模型返回 `logits`。
* 使用 `torch.argmax` 获取预测类别（Class ID），并将其映射为 "Positive" 或 "Negative" 输出。

## 总结：这段代码的优势

1. **参数高效**：只训练不到 1% 的参数（仅 P-Tuning 编码器部分），其余 BERT 参数全部冻结。
2. **克服离散 Prompt 缺点**：通过 LSTM+MLP 生成连续的 Prompt，比直接随机初始化或手动设计 Prompt 具有更好的泛化能力和稳定性。
3. **实现优雅**：直接利用 Hugging Face 的 `inputs_embeds` 接口绕过了词表限制，在底层完美实现了 Prompt 与文本的拼接。
