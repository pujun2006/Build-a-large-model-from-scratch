在大语言模型（LLM）的参数高效微调（PEFT）技术中，**Prompt Tuning** 和 **P-Tuning（含 P-Tuning v1 与 v2）** 都是基于“提示学习（Prompt Learning）”的思想发展而来的经典方法。它们通过冻结预训练模型主体、只训练少量的附加连续参数（Soft Prompts），实现了极高的高效性。

严格来说，**Prompt Tuning** 与 **P-Tuning** 在原生设计上是两种不同的优化路线。但在实际工程落地、架构演进（如 Hugging Face `peft` 库的设计）以及深度提示（Deep Prompt Tuning）的实践中，它们的思想经常被结合或共同探讨。

以下从核心机制、技术对比以及“如何协同/同时理解”三个维度进行深度解析。

---

### 一、 核心机制回顾

#### 1. Prompt Tuning (Lester et al., 2021)

* **核心思想**：在输入文本的 Embedding 层前面直接拼接 $k$ 个可训练的连续向量（Soft Prompts），形状为 $(k, d_{\text{model}})$。
* **运作方式**：
* 冻结预训练模型的全部权重。
* 只对这 $k$ 个向量进行梯度更新。
* 前向传播时，输入表示变更为：<img width="234" height="39" alt="1315c890-c45c-47ea-9aee-19be9de48100" src="https://github.com/user-attachments/assets/3b0af3c2-8201-42a9-b7e0-a51090d8eabb" />
。


* **特点**：极其轻量（参数量通常不足模型总量的 0.1%），但在**小模型（< 10B）上表现较差**，随着模型规模增大（$\ge 10\text{B}$），其性能逐渐逼近全量微调。

#### 2. P-Tuning (Liu et al., 2021 / P-Tuning v1 & v2)

* **P-Tuning v1**：针对 Prompt Tuning 在小模型上难以收敛、训练不稳定的问题，引入了 **MLP（多层感知机）或 LSTM** 来对 Prompt 的 Embedding 进行重新参数化（Re-parameterization）。即不直接优化 Prompt 向量，而是优化一个小型神经网络，由其动态生成 Prompt。训练完成后，通常会丢弃该网络，只保留生成的 Prompt。
* **P-Tuning v2 (Deep Prompt Tuning)**：借鉴了 Prefix-Tuning 的思想，将连续提示注入到模型的**每一层**（Layer），而不仅仅是输入层。这极大地增强了模型对复杂自然语言理解（NLU）任务和轻量级模型的适配能力。

---

### 二、 Prompt Tuning 与 P-Tuning 的核心差异

| 维度 | Prompt Tuning | P-Tuning (v1 / v2) |
| --- | --- | --- |
| **参数初始化** | 通常随机初始化或用词表中的 Embedding 初始化。 | 通过 MLP / LSTM 生成，缓解优化不稳定问题。 |
| **Prompt 注入位置** | 仅在**输入层（Input Embedding）**。 | **v1**：输入层；**v2**：模型**每一层 Transformer** 的 Key 和 Value（或输入）。 |
| **对模型规模的依赖** | 高度依赖大模型（大于等于10B 才展现出强竞争力）。 | 对中小型模型（如 BERT、Base/Large 级别的 LLM）同样高效。 |
| **计算与存储开销** | 极低（仅增加输入序列长度）。 | 稍高（v2 需要在每一层维护 Prompt，但相比全量微调仍极小）。 |

### 三、 如何在工程实践中“同时使用”或融合设计？

在现代 PEFT 框架（如 Hugging Face PEFT）中，这两者的边界在融合架构中逐渐模糊。如果你需要在项目中同时吸收两者的优势（例如在中小模型上实现深层、稳定的提示微调），通常会采用以下**融合策略**：

#### 1. 深度注入（P-Tuning v2 思想） + 独立连续提示（Prompt Tuning 结构）

* **做法**：不单单在 Embedding 层加 Prompt，而是在 Transformer 的**每一层**都引入可训练的连续张量。
* **代码层面的表现（以 PyTorch / Transformers 为例）**：
在定义自定义的 Prompt 模块时，为每一层注册可学习的参数矩阵 `prompt_embeddings`：
```python
import torch
import torch.nn as nn

class DeepPromptLayer(nn.Module):
    def __init__(self, num_layers, prompt_len, d_model):
        super().__init__()
        # 类似 P-Tuning v2 的多层连续提示矩阵
        self.prompts = nn.Parameter(torch.randn(num_layers, prompt_len, d_model))

    def forward(self, layer_idx, hidden_states):
        batch_size = hidden_states.size(0)
        # 获取当前层的 prompt，并扩展到 batch 维度
        layer_prompt = self.prompts[layer_idx].unsqueeze(0).expand(batch_size, -1, -1)
        # 拼接到当前层的隐状态前
        return torch.cat([layer_prompt, hidden_states], dim=1)

```



#### 2. 引入重参数化（P-Tuning v1 思想）优化 Prompt Tuning

* **痛点**：Prompt Tuning 直接优化 Embedding 容易陷入局部最优，收敛较慢。
* **优化**：在 Prompt Tuning 的初始化阶段，利用一个小型 MLP（类似 P-Tuning v1）来映射一组虚拟 Token ID 或通过前馈网络生成初始 Prompt 向量，从而加速训练初期收敛。

#### 3. 混合提示与任务特定路由

在多任务微调场景中，可以同时加载静态的 Prompt Tuning 嵌入向量（用于捕获通用领域风格）和动态的 P-Tuning 门控网络（根据输入动态调整深层提示），从而在保持参数极少的同时，兼顾对复杂语义的深层控制。

### 四、 面试与工程落地建议

1. **选型优先级**：
* 如果是 **超大模型（$\ge 10\text{B}$）** 且做生成任务（Generation），优先选择标准的 **Prompt Tuning** 或 **Prefix-Tuning**，实现简单且效果好。
* 如果是 **中小型模型（如 BERT、LLaMA-7B 以下）** 或复杂的 NLU 任务（如序列标注、文本分类），优先选择 **P-Tuning v2**（即 Deep Prompt Tuning），因为它在深层注入了微调能力，效果显著优于浅层 Prompt Tuning。


2. **显存与速度权衡**：
连续提示会增加序列长度（Seq Len），从而增加注意力机制（Attention）的显存开销（$O(N^2)$）。在实现时需注意控制 Prompt 长度（通常设为 `10` 到 `100` 之间）。
