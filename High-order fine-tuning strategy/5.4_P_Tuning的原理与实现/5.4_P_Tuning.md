P_Tuning.py代码是一个使用 **PyTorch** 和 **Hugging Face Transformers** 从零实现、非常标准且严谨的 **P-Tuning v1** 文本分类微调脚本。它完整地展示了 P-Tuning 的核心架构思想。

以下将这段代码拆解为三个核心部分进行逐段精讲：

---

### 一、 `PTuningEncoder`：P-Tuning 的灵魂（重参数化模块）

这段代码对应 P-Tuning 最具特色的部分：**Prompt Encoder**。

```python
class PTuningEncoder(nn.Module):
    def __init__(self, prompt_length, embed_dim, hidden_dim=768):
        super(PTuningEncoder, self).__init__()
        self.prompt_length = prompt_length
        self.embed_dim = embed_dim

        # 1. 底层可学习的原始嵌入
        self.raw_embeddings = nn.Embedding(prompt_length, embed_dim)

        # 2. 核心：Prompt Encoder (使用 MLP)
        self.mlp = nn.Sequential(
            nn.Linear(embed_dim, hidden_dim),
            nn.Tanh(),
            nn.Linear(hidden_dim, embed_dim)
        )

```

* **为什么不直接学 Embedding？**
在传统的 Prompt Tuning 中，直接优化一组孤立的连续向量往往非常不稳定，容易导致模型过拟合或难收敛。
P-Tuning 引入了 **Prompt Encoder（这里使用 MLP + Tanh 激活函数，原版还可以用 Bi-LSTM）**。模型实际优化的并不是最终的输入嵌入，而是通过 MLP 将一组基础参数“映射/转换”成最终的虚拟 Prompt 嵌入。这种重参数化（Reparameterization）极大地平滑了优化空间，显著提升了稳定性。
* **`forward` 逻辑**：
1. 生成形状为 `[batch_size, prompt_length]` 的虚拟 Token 索引。
2. 通过 `raw_embeddings` 查表得到初始向量。
3. 通过 `mlp` 进行非线性变换，输出最终的连续 Prompt 嵌入（形状为 `[batch_size, prompt_length, embed_dim]`）。



---

### 二、 `BertWithRealPTuning`：模型包装与前向传播

这部分负责将 P-Tuning 模块与冻结的 BERT 主干网络无缝结合。

```python
class BertWithRealPTuning(nn.Module):
    def __init__(self, prompt_length, embed_dim, model):
        super(BertWithRealPTuning, self).__init__()
        self.bert = model
        self.prompt_length = prompt_length

        # 1. 核心：冻结 BERT 主干网络
        for param in self.bert.parameters():
            param.requires_grad = False

        # 2. 实例化 P-Tuning Encoder
        self.p_tuning_encoder = PTuningEncoder(prompt_length, embed_dim)

```

* **冻结参数 (`requires_grad = False`)**：这是高效微调（PEFT）的关键。BERT 的 1.1 亿参数全部被锁死，不计算梯度、不更新权重，从而节省了大量的显存并防止灾难性遗忘。
* **前向传播 (`forward`) 的 5 个精妙步骤**：
1. **获取文本嵌入**：`text_embeddings = self.bert.bert.embeddings(input_ids)` —— 先把真实文本转成正常的 Token Embedding。
2. **生成 Prompt 嵌入**：`prompt_embeddings = self.p_tuning_encoder(...)` —— 通过刚才的 Encoder 生成虚拟 Prompt。
3. **拼接（Concatenation）**：`torch.cat((prompt_embeddings, text_embeddings), dim=1)` —— **这是核心操作**。把虚拟 Prompt 拼在真实文本的**最前面**，形成了 `[Prompt; Text]` 的组合嵌入。
4. **扩展注意力掩码（Attention Mask）**：`torch.cat([torch.ones(...), attention_mask], dim=1)` —— 必须把新增的 Prompt 部分对应的 Mask 设为 `1`，否则 BERT 在计算 Self-Attention 时会把这些虚拟 Token 当成填充（Pad）而忽略掉。
5. **送入主干网络**：注意这里传入的是 `inputs_embeds=combined_embeddings` 而不是传统的 `input_ids`，因为 BERT 已经跳过了自自带的 Embedding 层，直接从连续的嵌入向量开始计算。

### 三、 主程序：数据、优化器与训练循环

这部分负责让模型运转起来：

```python
if __name__ == "__main__":
    ...
    # 1. 准备示例数据与 DataLoader
    texts = [...]
    dataset = TensorDataset(...)
    dataloader = DataLoader(dataset, batch_size=2, shuffle=True)

    # 2. 实例化包装模型并放到设备上
    p_tuned_model = BertWithRealPTuning(prompt_length, embed_dim, base_model)
    p_tuned_model.to(device)

    # 3. 关键：优化器只更新 P-Tuning 模块的参数！
    optimizer = optim.AdamW(p_tuned_model.p_tuning_encoder.parameters(), lr=5e-4, weight_decay=0.01)
    criterion = nn.CrossEntropyLoss()

```

* **`optimizer` 的精髓**：`p_tuned_model.p_tuning_encoder.parameters()` 确保了优化器**只对 P-Tuning Encoder 内部的参数（`raw_embeddings` 和 `mlp`）进行梯度更新**，BERT 主干网络的参数在优化时会被自动忽略。
* **训练循环**：标准的 PyTorch 训练套件（清空梯度 $\rightarrow$ 前向传播 $\rightarrow$ 计算 Loss $\rightarrow$ 反向传播 `loss.backward()` $\rightarrow$ 梯度更新 `optimizer.step()`）。

### 总结

这段代码完美诠释了 P-Tuning v1 的工程实现精髓：

1. **不改动模型结构定义**，而是通过**在输入端“偷梁换柱”**（直接拼接连续嵌入 + 扩展 Mask），让冻结的 BERT 误以为这些虚拟 Token 就是正常的上下文。
2. 通过一个轻量级的 **MLP 动态生成提示**，兼顾了训练稳定性和微调效果。
