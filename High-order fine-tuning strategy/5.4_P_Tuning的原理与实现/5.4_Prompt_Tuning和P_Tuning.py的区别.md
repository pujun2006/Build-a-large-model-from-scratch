**Prompt Tuning** 和 **P-Tuning**（包括 P-Tuning v1 和 v2）都是大语言模型（LLM）中经典的参数高效微调（PEFT, Parameter-Efficient Fine-Tuning）方法。它们的共同核心思想是：**冻结预训练模型的大部分权重，只训练少量的附加连续参数（即“软提示”/Soft Prompts）**。

虽然目标相似，但它们在**插入位置、初始化方式、对模型大小的依赖以及适用任务**上有显著区别。以下是详细的对比：

---

### 一、 核心概念与原理区别

#### 1. Prompt Tuning（提示微调）

* **提出者**：Google 团队（Lester et al., 2021）。
* **核心机制**：在输入文本的 **Embedding 层最前方**直接拼接一组可学习的连续向量（Virtual Tokens）。
* **特点**：
* **结构极其简单**：它把提示视作一个独立的可训练矩阵（形状为 `[prompt_tokens, embedding_dim]`），直接参与反向传播。
* **高度依赖模型规模**：论文表明，Prompt Tuning 在小模型上表现较差；只有当模型参数量达到 **10B（100亿）以上**时，其性能才能逼近甚至赶上全参数微调。



#### 2. P-Tuning（清华大学唐杰团队，Liu et al., 2021/2022）

P-Tuning 经历了两个主要版本，通常指代时会结合 v1 和 v2：

* **P-Tuning v1**：
* **核心机制**：允许将可学习的虚拟 Token 插入到输入文本的**任意位置**（不局限于前缀），并且引入了一个 Prompt Encoder（通常由 LSTM + MLP 组成）来生成这些虚拟 Token 的 Embedding。
* **优势**：通过 LSTM/MLP 建模了提示向量之间的依赖关系，缓解了直接优化离散/连续向量的不稳定性。


* **P-Tuning v2**（ACL 2022）：
* 为了解决 P-Tuning v1 和 Prompt Tuning 在小型模型、NLU（自然语言理解）任务以及复杂序列标注（如 NER）上效果不佳的问题，P-Tuning v2 借鉴了 Prefix-Tuning 的思想，将连续提示注入到 **Transformer 的每一层**（Deep Prompt Tuning），而不仅仅是输入层。



---

### 二、 核心维度对比表

| 对比维度 | Prompt Tuning | P-Tuning (v1 / v2) |
| --- | --- | --- |
| **提示插入位置** | 仅在输入层（Input Embedding）最前方 | **v1**：可插入输入序列的任意位置。<br>

<br>**v2**：深入到 Transformer 的**每一层**（多层注入）。 |
| **参数生成方式** | 直接定义一个可学习的参数矩阵（Embedding Lookup） | **v1/v2**：通常使用一个 Prompt Encoder（如 LSTM 或 MLP）来动态生成或初始化提示向量。 |
| **对模型规模的依赖** | 强依赖。参数量需 $>10\text{B}$ 才能展现优势。 | 弱依赖。即使在小型模型（如 $<1\text{B}$）或 NLU 任务上也能取得极佳效果。 |
| **擅长的任务类型** | 文本生成、大规模语言模型的下游适配。 | 广泛适用于 **NLU（自然语言理解）**、分类、序列标注（如命名实体识别）及复杂生成任务。 |
| **代码/库中的体现** | Hugging Face `peft` 中对应 `PromptTuningConfig`。 | Hugging Face `peft` 中对应 `PainingConfig` 或类似的多层结构配置。 |

---

### 三、 从代码实现层面（如 `.py` 脚本逻辑）看两者的不同

如果你在查阅或编写相关的微调脚本（如 `prompt_tuning.py` vs `p_tuning.py`），它们的差异主要体现在：

1. **模版与数据处理（Data Collator / Template）**：
* **Prompt Tuning**：代码逻辑非常直接，在输入 Token IDs 前面固定拼接 $N$ 个虚拟 Token 的 ID 即可。
* **P-Tuning**：允许在模板（Template）中定义占位符（例如 `{"text": "...", "point": "prefix"}`），需要更复杂的定位逻辑把虚拟 Token 插入到文本的中间或特定位置。


2. **模型结构包装（Model Wrapper / PEFT Config）**：
* **Prompt Tuning** 的模型修改只发生在模型的 `word_embeddings` 阶段，通过扩展 Embedding 矩阵的大小或在输入前加一层 Hook 来注入虚拟 Token。
* **P-Tuning（尤其是 v2）** 会深入到模型的每一个 Transformer Block，通过修改 Attention 层的 Key/Value（或者直接拼接在隐层状态前）来注入 Prompt，因此其代码需要遍历模型的 `layers` 并进行注册。



### 总结

* 如果你的任务是**超大模型（百亿参数以上）的生成任务**，且追求极致的简单和低参数量，**Prompt Tuning** 是一个轻量、优雅的选择。
* 如果你面对的是**中小规模模型、NLU 任务（如分类、抽取）**，或者需要提示词在输入中灵活穿插、甚至多层注入，**P-Tuning（特别是 P-Tuning v2）** 通常能提供更强的收敛能力和更高的准确率。
